# Leetcode - One Problem, Multiple Ways

Most LeetCode guides focus on **finding the standard or optimal solution** to a problem, usually by applying a well-known algorithmic pattern.

This repository is created for a different purpose.

---
## 💡 Why this repository exists
While practicing problems, I realized that:

- Many problems can be solved in **multiple fundamentally different ways**
- What we often call the “optimal” solution usually **optimizes for one dimension**, while **sacrificing others**
- These trade-offs are rarely discussed in typical solution guides

In real engineering work, trade-offs are everywhere:
- time vs space  
- simplicity vs extensibility  
- theoretical optimality vs implementation risk  

This repository is an attempt to **make those trade-offs explicit**.

Instead of asking  
> “What is the best solution?”  

I want to ask  
> “What are the different ways to think about this problem, and what do we give up in each approach?”

---


## 🧠 How problems are explored here

For each problem, I try to:

- Solve it using **multiple paradigms** (e.g. DFS + memo, DP table, BFS, data-structure-based)
- Clearly state:
  - what the state represents
  - how transitions work
  - what assumptions are being made
- Compare solutions in terms of:
  - time & space complexity
  - implementation complexity
  - readability and mental load
  - suitability under different constraints

The goal is not to collect answers, but to **build intuition**.

---

## ⌨️ Thinking in “keyboard-friendly” form

All explanations are written in a **structured, keyboard-embeddable format**:
- short definitions
- bullet-point reasoning
- step-by-step state transitions

This is intentional.

In interviews, we don’t have time to “re-derive” ideas from scratch.
Being able to **replay a reasoning path clearly and quickly** is often more important than remembering code.

This repository is designed to support that kind of **mental recall under pressure**.
